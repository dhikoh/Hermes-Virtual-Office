## 3. Decisions (D1 - D3)

- **Decision D1: Tool Matrix Scope Alignment**  
  *Decision:* Removed unimplemented tool names (`write_plan`, `write_docs`, `browse_localhost`, `fetch_web_content`, `web_search`, `save_research`) from role matrices instead of implementing stub functionality in this patch.  
  *Rationale:* Strict remediation protocol prohibits scope creep and unverified code additions. Unimplemented capabilities are explicitly documented under Known Limits.

- **Decision D2: Workspace Path Validation Scope**  
  *Decision:* Validated agent workspace path inputs by rejecting path traversal (`..`), system roots (`/`, `C:\`), and empty strings, falling back to deterministic ID-based workspaces (`workspace-<agentId>`). Existing workspaces are retained for backward compatibility.  
  *Rationale:* Provides input hygiene without breaking existing persisted agents, while explicitly acknowledging this is path validation and not an OS-level sandbox.

- **Decision D3: Multi-User Authentication Variable Standardization**  
  *Decision:* Standardized authentication gating on canonical `MULTI_USER` environment variable in `server/index.js` and documented it in `.env.example`.  
  *Rationale:* Eliminates conflicting legacy alias confusion (`STUDIO_MULTI_USER`) while maintaining strict token checks when `MULTI_USER=true`.

## 4. Known Limits & Items Not Run

- **Items Not Run:**
  - `docker build` & volume persistence restart check: Docker daemon is unavailable on the local Windows environment. Noted as `NOT RUN` per strict reporting protocol.
  - Manual Windows service script execution (`stop-hermes.bat` against running background stack): Verified programmatically via unit tests `tests/unit/adapterShutdown.test.ts` and `tests/unit/startStack.test.ts`.

- **Known Limits:**
  - `write_docs` and `browse_localhost` are not implemented; Writer and QA roles do not possess document authoring and local browser testing tools.
  - Agent workspace directories are retained upon agent dismissal to prevent permanent data loss.
  - Workspace validation prevents path traversal but does not provide hardware or OS-level sandbox containment.
